# R7000 unpacking and validation

Supported chain: NETGEAR CHK -> Broadcom TRX v1/v2 -> LZMA-alone kernel
and SquashFS v4.0 with XZ compression. All parsing and extraction in this
chain runs in Rust, behind a Python adapter for Binary Ninja's Container Browser.
The standalone `firmware-unpack` executable uses the same Rust implementation.
Known child layers explicitly select the Rust decoders, so Binary Ninja's
parallel built-in TRX decoder does not bypass the native CRC check. When opening
a standalone TRX image, choose `Broadcom TRX firmware` (`Trx`) to use this decoder.

## Real sample

- Firmware: `R7000-V1.0.9.88_10.2.88.chk`
- Size: 31,649,850 bytes
- SHA-256: `afb847c8772a8d59aabf026d01f0285ce14b03505d3a443e31afe6ba8ba8d379`
- [Vendor download](https://www.downloads.netgear.com/files/GDC/R7000/R7000-V1.0.9.88_10.2.88.zip)
- [GRIMM research](https://grimmcyber.com/soho-device-exploitation/)

The CHK header is 58 bytes. TRX starts at `0x3a`. The LZMA stream starts
at file offset `0x56`; the SquashFS filesystem starts at `0x21e59a`.
The decompressed kernel is 5,436,480 bytes. The filesystem contains 1,578
regular-file paths (symlinks and special files are excluded).

CHK header and payload lengths are validated. The CHK vendor checksum fields
are not interpreted; the inner TRX CRC32 is checked before exposing partitions.
TRX partition offsets must be ordered and bounded. Opaque prefix/trailer
bytes are exposed as separate children rather than discarded.

LZMA-alone accepts both known-size streams without an end marker (as in
this R7000 image) and streams with an end marker. Decoding is capped at
512 MiB output and 64 MiB decoder memory, with dictionary headers restricted
to at most 32 MiB. Malformed/truncated streams and non-padding trailers fail.
XZ SquashFS parsing uses the `backhand` reference library, with input and
per-file bounds checks. Original paths remain case-sensitive in Container
Browser. Standalone disk extraction maps case collisions to distinct names,
recorded in per-archive `.ffe-paths.tsv` files. Nested layers live in
sibling `<member>.unpacked/` directories; the same CLI handles every native
format through the generated registry. It requires a new output directory and
does not create firmware-supplied symlinks or device nodes.

## Independent comparison

Build the Rust backend, and obtain upstream
[SquashFS tools 4.6.1](https://github.com/plougher/squashfs-tools/releases/tag/4.6.1)
with XZ support. No external extraction tool is used by the plugin itself.

```sh
cargo build --release --locked
python3 scripts/verify_r7000.py /path/to/firmware.zip \
  --unsquashfs /path/to/unsquashfs --report /path/to/verification.json
```

The verifier pins the original firmware SHA-256, checks the extracted TRX
against the CHK payload, and compares the kernel byte-for-byte to Python's
liblzma decoder. It compares the complete regular-file name set and every
file's bytes against upstream `unsquashfs -cat`. Using `-cat` avoids host
filesystem case collisions in the independent reference extraction.
The report records a SHA-256 and length for each original path.

Validation on 2026-10-21 passed for the real image: all 1,578 regular files
matched upstream unsquashfs, and the 5,436,480-byte kernel matched liblzma.
The kernel SHA-256 is
`a2364a92ce6d905bf9682e1f09f1568c8ac8e1bebcebeb6702bafcfddcfcea19`.
The registry refactor retains those byte-for-byte regressions. See
[the format guide](ADDING_A_FORMAT.md) for fixture discovery, the 1,000-format
candidate-selection test, and the isolated extension-contract check.

Pass `--disk-tree /path/to/output` to also verify a standalone extraction,
including its filename mapping and intermediate artifacts. Real firmware and
extraction artifacts belong under ignored `artifacts/`, outside Git fixtures.

For a full end-to-end Binary Ninja test using that report:

```sh
FFE_R7000_FIRMWARE=/path/to/R7000-V1.0.9.88_10.2.88.chk \
FFE_R7000_REPORT=/path/to/verification.json BN_DISABLE_USER_PLUGINS=1 \
./scripts/run_tests.sh -v --confcutdir=tests
```

## Minimal regression fixtures

`scripts/generate_r7000_fixtures.py` generates `netgear_chk`, `trx`,
`lzma_alone`, `squashfs_mksquashfs` and corrupt variants. The nested fixture
checks hashes at each layer, not just the first extracted child. The kernel
is small synthetic ARM-shaped data, compressed by Python's liblzma encoder.
The filesystem contains a small fragment file and a compressed file spanning
several blocks; upstream `mksquashfs 4.6.1` creates the filesystem. Wrapper
headers are synthetic, with the TRX CRC independently calculated by zlib.

```sh
python3 scripts/generate_r7000_fixtures.py --mksquashfs /path/to/mksquashfs
```

The old `squashfs` fixture's incomplete hand-built metadata was replaced by
an upstream-tool image with identical `hello.txt` bytes and expected hash.
No vendor firmware bytes are included in committed regression fixtures.
